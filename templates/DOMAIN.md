# DOMAIN (경량 모델) — 과제 데이터로 확인한 것만 남기고 나머지는 지운다

표기: [확인] 데이터·담당자 답으로 확인 / [가정] 아직 확인 안 함 / [질문] 담당자에게 물을 것

## 1. 개체와 관계 (제조 공정 데이터의 흔한 구조)
- 계층: 제품 → lot → wafer → die. 행 단위와 판단 단위가 다르면 판단 단위로 먼저 묶는다
- 사건 사슬: `불량그룹 → 불량 → (관측된) 공정 → 설비/챔버 → 정비 이력`, 별도로 `검출(검사) 공정 → 불량`
- step 종류: **가공 step**(불량을 만들 수 있음) vs **검사·측정·준비 step**(불량을 발견·기록함)
- 이벤트: 정비(고장·예방·상태기반 모두), 부품 교체, recipe 변경, 알람
- 경로가 길면 질문에 답하기 어렵다 → 먼저 "답해야 할 질문"을 정하고 필요한 관계만 둔다. 데이터가 없어 답할 수 없는 질문(레시피 파라미터, 센서, 조치 효과 등)은 범위 밖으로 명시한다

## 2. 규칙 유형 (내용은 과제마다 담당자에게 확인)
| 유형 | 기본 가정 | 어디서 강제 |
|---|---|---|
| 판정 공정 ≠ 원인 공정 | 검사·측정·준비 step은 원인 후보에서 제외 (물리적 파손류는 기록된 곳이 발생한 곳일 수 있음 [질문]) | 데이터·쿼리 |
| 질문 목적별 분기 | "몇 개냐"(집계)는 포함, "왜냐"(원인)는 제외하는 레코드가 있다 | 코드 분기 |
| 분석 대상 아닌 레코드 | 샘플·모니터링 코드, 사유 공란 → 수량엔 포함, 원인 추론에선 제외 | 데이터 |
| 가짜·인프라 설비 | 반송·대기·시스템 처리 ID, 공용 설비는 공통성 분석에서 제외 | 데이터 |
| 귀속 경로 | 불량 테이블의 설비 칸이 자리표시 값일 수 있다 → 공정 이력으로 귀속 | 코드 |
| 시점 | 원인 후보는 불량 시점 **이전** 이력만. 변경점은 이상일에서 고정 기간 거슬러 조회. 시작이 아니라 **완료** 시점 값 | 코드 |
| 이상 판정 | 기준선 대비 급증 또는 N일 연속 증가. 기준은 감이 아니라 데이터로 (중앙값·MAD 기반 상승 판정, 연속 일수별 실제 이상 비율로 N 선택). 소량 설비는 후보 제외 | 코드 |
| 정비 경과 | 설비별 정비 간격의 기준 주기를 데이터로 구하고 경과·누락을 파생 지표로 | 코드 |
| 수율·분모 | 첫 측정 기준, 폐기·미검사 제외 후 개수 따로 보고 [질문] | 코드 |
| 표시 | 사용자에겐 이름을 보여주고 원시 ID는 숨김. 마스터에 없으면 ID로 대체 | 화면 |
→ 구조는 **규칙 → 파생 변수(코드가 계산) → LLM 입력(판단 결과만)** 3층. 규칙을 받으면 먼저 **데이터 / 쿼리·코드 / LLM 중 어디서 강제할지** 정한다. 판정·제외·시점·계산은 LLM에 맡기지 않는다.

## 3. 데이터 함정 체크
- [ ] **단일 ID가 유일하지 않음** (날짜·사업장·재작업에 걸쳐 재사용) → 복합키
- [ ] **시스템마다 설비 표기가 다름** → 조인 가설별 매칭률을 각각 재고 가장 높은 경로 선택. 미매칭은 목록으로 남기고 질문으로
- [ ] **행 팽창** (작업 1건 × 자재 N건) → 이벤트 키로 DISTINCT
- [ ] **이벤트 종류 혼재** (시작·완료·반려) → 완료만, 완료 시점 값
- [ ] **날짜 기준 불일치** (업무일 vs 등록 시각, 형식 차이, UTC/KST) → 테이블마다 기준 하나로
- [ ] **변환 실패를 0으로 채움** → 실패시키거나 표시한다
- [ ] **타입 불일치** (decimal vs int vs string 키) → 명시적 CAST
- [ ] **삭제 플래그 누락 vs false** → `== false` 대신 `!= true`
- [ ] **0을 "없음"으로 취급** → 0은 유효값
- [ ] **완전 중복·이중 등록** → 담당자 확인 후 제거
- [ ] **초대형 원천** → 날짜 필터 먼저, 하루치로 시험, 범위를 좁힌 뒤 집계

## 4. 원인 추적 절차 (공통성 분석)
1. **감지**: 사유별·일별 집계 → 급증 또는 연속 증가일. 이상일은 진입점이지 원인일이 아니다
2. **대상**: 복합키로 영향 단위를 뽑고 분석 대상 아닌 코드 제외
3. **공통성**: 해당 사유에 대해 step × 설비를 **영향 단위 고유 수**로 순위. 이전 이력만, 검사 step·가짜 설비·소량 설비 제외. 후보가 많으면 상위 K로 압축하되 전체 합계는 남긴다
4. **변경점**: 후보 설비의 정비·이벤트를 고정 기간 거슬러 조회 (시간대 맞춘 뒤). 유형·조치·이상일까지 간격을 보고
5. **대조**: 급증일 vs 평상일의 사유 코드 구성 비교. 코드로 좁히면 전체 1위가 아닌 설비가 올라올 수 있다
6. **반증**: 같은 설비의 다른 기간은 정상인가, 같은 기간 다른 설비는 정상인가. 상위 단위(lot) 안에 불량이 **집중**되면 설비, **분산**되면 원재료를 의심
7. **수렴**: 서로 다른 진입점(급증 / 집중-분산 패턴)이 같은 후보로 모이는가
8. **출력**: "후보 + 근거(기간, 대상 목록, 수량, 경로)" + "데이터 사실 / 추론" 구분 + (요구되면) 권고 조치는 "확인할 것" 수준으로. 데이터가 없으면(예: 정비 이력 없는 설비) 추론 보류하고 한계로 표시. 최종 판단은 엔지니어

## 5. 현업 질문 흐름과 대응
- 흐름은 **무엇이 → 얼마나 → 어디서 → 왜** 순서로 깊어진다 (업무 단계로는 대상 추출 → 연관 이력 추적 → 상관 도출 → 요약·권고). 화면도 이 순서로 설계한다
- 실제 질문은 **이어 묻기**다: "그중 1위는?", "그 설비 추이는?". 앞 답의 대상(날짜·설비·코드)을 상태로 들고 있어야 한다
- 집계·현황 질문은 표·쿼리로, "왜·경로" 질문은 이력 연결(경로)로 답하고 **경로 자체를 근거로 보여 준다**
- 인자가 빠진 질문은 빠진 것만 되묻는다. 기간 없는 추상 질문은 최근 사례 목록을 선택지로 제시
- **"이거 믿을 수 있나?"**에는 출처, 수치, 처리 경로, 범위를 정한 이유를 보여 준다
- 범위 밖 질문(여러 그룹 동시 비교, 조치 후 부작용 등)은 범위 밖으로 명시한다

## 6. 제조 운영 참고 (담당자 질문·함정 찾기용. 과제 정의가 우선)
**수율·테스트**
- 흐름: 공정 → 웨이퍼 테스트(die 단위 pass/fail + bin) → 조립 → 패키지 최종 테스트 (→ 번인)
- 수율 정의가 여럿: 라인(투입 대비 남은 wafer), die(양품 die / 전체 die), 최종, 누적(=곱). 어느 것인지 [질문]
- bin: 보통 1번대가 양품, 나머지 불량 유형. 재테스트가 있으면 첫 결과 기준 vs 최종 결과 기준 [질문]
- 메모리는 수리(여분 셀 대체) 후 양품이 되는 die가 있다 → 수리 전·후 수율 구분 [질문]
- 웨이퍼 맵 패턴은 원인 단서: 가장자리·링(막 균일도), 선형 스크래치(이송·연마), 국소 군집(파티클), 중심, 전면 랜덤. 가장자리 die 제외 규칙 [질문]. 좌표 (x,y) 기준 방향 확인

**공정 관리 (SPC)**
- 관리 한계(데이터로 계산, 중심 ± 3σ) ≠ 규격 한계(설계·고객이 정함). 둘을 섞지 않는다
- 이상 규칙: 한계 밖 1점, 한쪽 연속 7~9점, 연속 6점 증가·감소, 3점 중 2점이 2σ 밖 등. 어떤 규칙을 쓸지 [질문]
- Cp/Cpk: 규격 대비 산포·치우침. 합격 기준값 [질문]
- σ·중심선은 정상 기준 기간에서 구해 고정한다 (이상 기간을 넣으면 한계가 넓어져 못 잡는다)

**설비 센서 시계열**
- 시각이 아니라 **recipe step 기준**으로 맞춘다. step별 요약(평균, 표준편차, 최대, 기울기)
- 기준 파형과 비교. step 시작·끝 과도 구간 제외 여부 [질문]
- 센서가 많으면 변화량 큰 순 상위만 보고, 서로 비슷한 센서는 묶는다

**설비 고장 예측 (센서 → 남은 수명·알람)**
- 목표가 "이상 감지"인지 "고장 시점(남은 수명) 예측"인지 먼저 [질문]. 고장 이력이 적으면 예측 대상 정의부터 합의
- 센서 노이즈는 이동평균·지수평활로 줄이고 창 크기는 근거(검증 점수)로 정한다. 운전 조건이 여럿이면 조건별로 정규화
- 변수 선택은 통계 검정·상관으로 근거를 남기고, 같은 설비의 시간 순서를 지켜 학습/검증을 나눈다 (섞으면 누수)
- 평가 지표는 비용에 맞춘다: 늦게 맞히는 것(고장 뒤 알람)이 일찍 맞히는 것보다 비싸면 비대칭 가중 오차. 임계값 알람이면 놓침·헛알람 수로도 보고
- 결과는 비용(정비비·정지 시간)으로 번역해 보여 준다. 기준선(정기 정비, 단순 규칙)과 비교

**운영 지표**
- 설비종합효율(OEE) = 가동률 × 성능 × 양품률. 고장 간격 평균(MTBF), 수리 시간 평균(MTTR)
- 재공(WIP), cycle time(투입~완료), Q-time(공정 사이 대기 제한, 넘으면 재작업·폐기), hold(보류 lot), rework
- 상태 이력은 (시작, 끝) 구간으로 바꿔 계산하고 겹침·빈 구간을 확인

**비제조 업무 과제일 때** (문서·메일·티켓·규정 질의)
- 답에 원문 근거(파일·조항·행)를 붙인다. LLM에 보내기 전에 `mask.py`로 가리고, 화면에서만 필요한 만큼 복원
