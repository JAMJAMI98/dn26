# frontend 규칙

## 구조 (Feature-Sliced 축소형)
| 위치 | 책임 |
|---|---|
| src/app/ | 라우팅, 역할별 레이아웃, 인증 상태, 라우트 가드(미로그인 → 로그인, 다른 역할 → 403 화면) |
| src/pages/ | 화면 단위. 업무 부품을 배치만 한다 |
| src/entities/ | 업무 개념 단위 부품(화면 명세의 블록 1개 = 파일 1개). 조회·표시 |
| src/shared/ | api 클라이언트(토큰 첨부, 401 → 로그인, 오류 형식 해석), ui(기본 부품·토큰), lib, config |

## 작은 디자인 시스템 (shared/ui)
- 토큰: 색·간격·글자 크기·둥글기. 색을 바꿀 때는 토큰 값만 바꾼다.
- 기본 부품: Layout, Button, Table(정렬, 숫자 오른쪽 정렬), Card(지표), Form 필드(검증 메시지), Badge, ConfirmDialog, 상태 4종(Empty·Loading·ErrorBox·Result), Graph(SVG 노드·엣지·라벨 겹침 회피), LineChart(시간·순서 축 + 기준선 + 표시점), BarChart(그룹 막대), GridMap(격자 칸 상태색 + 표시점). A안은 `shared/ui/Chart.tsx`·`GridMap.tsx`, B안은 `shared/ui/charts.js`(같은 인자).
- 업무 부품은 기본 부품만 조합한다. 개별 인라인 스타일·새 색상을 만들지 않는다.

## 화면 명세가 먼저
- `docs/05_design.md`의 화면 명세(역할별 화면 → 블록 → 보여 줄 숫자·동작·상태)를 따른다. 명세에 없는 블록을 만들지 않는다.
- 블록마다 상태 4종(처음·처리 중·오류·결과)을 보인다. 오류는 사용자 말로 + 다음 행동.

## 표시 규칙
- 시각은 HH:MM(날짜가 다르면 MM/DD HH:MM), 숫자에는 단위, 큰 수는 천 단위 구분.
- 사용자에게 보이면 안 되는 것: 파일명·CSV·좌표(위경도)·ISO 시각 문자열·내부 ID·가중치 같은 알고리즘 용어. 필요하면 상세 펼침 안에.
- 결과가 어떤 데이터·설정으로 만들어졌는지와 "이전 데이터 기준" 여부를 화면에 표시한다.
- 파일 업로드·파일 선택창·저장창을 만들지 않는다(과제가 요구하면 예외). 내보내기는 화면 표시·복사 또는 서버 파일.

## 수정을 받을 때
`[부품] [현재] [원하는 것] [완료 기준] [건드리지 말 것]` 형식으로 받은 범위만 고친다. 확인: `make test`(A안 tsc, B안 node --check), 화면은 사용자가 직접 확인.

## B안(바닐라 JS)일 때
- 같은 구조를 `.js` ES 모듈로: `pages/*.js`는 `({navigate, user}) => 요소`를 돌려주고, 라우트는 `app/router.js`의 ROUTES에 추가한다.
- 요소는 `shared/ui/dom.js`의 `h()`로 만든다. `innerHTML`에 데이터를 넣지 않는다(문자열은 항상 텍스트로).
- 빌드가 없다. 파일을 고치면 새로고침만 한다.
