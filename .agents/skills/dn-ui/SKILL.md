# 화면 (frontend/AGENTS.md 규칙을 따른다)

## 1. 명세 먼저 (docs/05_design.md 화면 명세 표)
- 역할마다: 들어오는 목적 한 줄 → 첫 화면에 보일 핵심 숫자 2~3개 → 블록 3~5개(위→아래) → 블록마다 부품 이름(entities), 보여 줄 값·동작·상태 4종.
- 결과 화면에는 "어떤 데이터·설정으로 만든 결과인지"와 이전 데이터 기준 여부.
- 그래프·도식은 읽기 전용 기본 배치를 먼저(예: 순서대로 한 줄, 겹침 0). 확대·드래그 같은 조작은 필수 기능이 다 된 뒤.

## 2. 구현
- shared/ui 기본 부품만 조합. 새 색·인라인 스타일 금지(색은 토큰 값만).
- API는 docs/05 API 계약대로. 계약 변경이 필요하면 창 A에 요청을 docs/05에 적고 기다리지 말고 가짜 응답으로 화면을 먼저 만든다.
- 표시 규칙: HH:MM, 단위, 천 단위 구분. 파일명·CSV·좌표·ISO 문자열·내부 ID·알고리즘 용어를 사용자에게 보이지 않는다.
- 업로드·파일 선택창·저장창 없음(과제가 요구하면 예외: 그때는 크기 제한·형식 검증·오류 행 표시). 내보내기는 화면 표시·복사 또는 서버 저장.

## 3. 확인
- `npm run typecheck` PASS, `npm run build` PASS.
- 사용자에게 미리보기에서 누를 순서 3~5단계를 준다(HUMAN_CHECK). 자동 브라우저 도구가 이미 있을 때만 스크린샷.

## 4. 수정 지시 받는 형식
`[부품] [현재] [원하는 것] [완료 기준] [건드리지 말 것]`. 받은 부품만 고친다. 여러 건이면 번호 순서대로 하나씩 커밋은 창 A가.
