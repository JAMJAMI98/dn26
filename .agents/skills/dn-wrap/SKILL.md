# 마무리 (1·2절 문서 초안은 창 B가 +125분부터, 3·4절 점검과 커밋은 창 A가 종료 25~20분 전)

1. **과제 지정 문서**: HOW_TO_RUN·AI_COLLABORATION은 과제 README 양식 그대로, 내용은 docs에서 옮긴다(새로 지어내지 않는다). 사람이 읽는 문장으로, 내부 번호 남발 금지.
   - HOW_TO_RUN: 목적·범위 / 스택 / 준비(환경변수 이름만, 비밀번호를 비우면 `backend/runtime/initial-credentials.txt`에 생기며 그 파일을 여는 명령) / 실행 명령과 주소 / 역할별 이용 순서와 대표 결과 / 테스트 / 가정·제한. 설계 기준과 방법은 docs/05·06 요약. 골격 출처 한 줄(공개 키트 골격: 인증·작업·배포. 업무 로직·화면은 이번 과제에서 작성).
   - AI_COLLABORATION: LOG의 `#Q1` `#Q3` 항목에서 고른다. 각 사례: 상황 → AI가 한 것 → 내가 확인한 방법(명령·결과) → 받아들임/고침/버림과 이유.
2. **docs/08 설명 카드** 7항목을 사람 말로 채운다(7번 핵심 결정 집중은 문서에서 가장 크게 다룬 결정 = 사용자가 가장 잘 설명할 수 있는 것)(파일:함수, 대표 숫자, 확인 명령 포함). 사용자가 G5에서 읽는다.
3. **docs/07** 최종 표: R·C별 상태와 근거, 확인 못 한 것과 이유.
4. **제출 점검**
   - 제출물 이름·경로가 README와 같은가, README·원본 데이터가 그대로인가(`git diff --stat`).
   - 문서의 실행 명령을 새 터미널에서 복사해 한 번 실행.
   - 비밀값: `git log -p | grep -iE "password|secret|token|api_key"` 결과에 실제 값 없음. .env는 추적 안 됨.
   - 제출 트리 정리: 실험 찌꺼기(scratch, 임시 파일), 설명 없는 폴더, 점 파일이 섞이지 않았나. 남길 것은 HOW_TO_RUN에 한 줄 설명.
   - 세션 히스토리 조건(본인 에이전트 환경 사용 시)과 사용 스킬 포함 여부 확인.
   - `python3 /tmp/dn/tools/langcheck.py` 통과.
   - 제출 폴더 전체가 후속 문답 출제 재료다: 사용자가 설명할 수 없는 문서·문장·잡파일은 지운다.
5. **최종 커밋은 종료 20분 전**: `git status --short` → 만든 파일만 이름으로 add → `docs: 제출 문서와 최종 검증`. 실패하면 사용자에게 명령 한 줄.
6. **모의 문답**(시간이 되면 창 B, 5분): docs/08 기준 예상 질문 3개(하나는 전제를 일부러 틀리게)를 한 개씩 낸다. 사용자는 코드를 보지 않고 1~3문장으로 답하고, 틀린 사실·근거 없는 숫자·과장만 짚는다. 문서와 코드가 어긋나면 문서를 코드에 맞춘다.
7. 보고: 남은 HUMAN_CHECK, 사용자가 읽을 것(docs/08), 제출 시작 시각.

대화가 길어지면 언제든: PLAN 상황판을 갱신하고 새 세션에서 "AGENTS.md(AGENTS.kit.md가 있으면 그것도)와 PLAN.md 읽고 이어서".
