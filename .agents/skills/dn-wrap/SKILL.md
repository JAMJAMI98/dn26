# 마무리 (창 A, 문서 초안은 창 B 가능)

1. **과제 지정 문서**: HOW_TO_RUN·AI_COLLABORATION은 과제 README 양식 그대로, 내용은 docs에서 옮긴다(새로 지어내지 않는다). 사람이 읽는 문장으로, 내부 번호 남발 금지.
   - HOW_TO_RUN: 목적·범위 / 스택 / 준비(환경변수 이름만) / 실행 명령과 주소 / 역할별 이용 순서와 대표 결과 / 테스트 / 가정·제한. 설계 기준과 방법은 docs/05·06 요약.
   - AI_COLLABORATION: LOG의 `#Q1` `#Q3` 항목에서 고른다. 각 사례: 상황 → AI가 한 것 → 내가 확인한 방법(명령·결과) → 받아들임/고침/버림과 이유.
2. **docs/08 설명 카드** 6항목을 사람 말로 채운다(파일:함수, 대표 숫자, 확인 명령 포함). 사용자가 G5에서 읽는다.
3. **docs/07** 최종 표: R·C별 상태와 근거, 확인 못 한 것과 이유.
4. **제출 점검**
   - 제출물 이름·경로가 README와 같은가, README·원본 데이터가 그대로인가(`git diff --stat`).
   - 문서의 실행 명령을 새 터미널에서 복사해 한 번 실행.
   - 비밀값: `git log -p | grep -iE "password|secret|token|api_key"` 결과에 실제 값 없음. .env는 추적 안 됨.
   - 제출 트리 정리: 실험 찌꺼기(scratch, 임시 파일), 설명 없는 폴더, 점 파일이 섞이지 않았나. 남길 것은 HOW_TO_RUN에 한 줄 설명.
   - 세션 히스토리 조건(본인 에이전트 환경 사용 시)과 사용 스킬 포함 여부 확인.
   - `python3 /tmp/dn/tools/langcheck.py` 통과.
5. **최종 커밋은 종료 20분 전**: `git status --short` → 만든 파일만 이름으로 add → `docs: 제출 문서와 최종 검증`. 실패하면 사용자에게 명령 한 줄.
6. 보고: 남은 HUMAN_CHECK, 사용자가 읽을 것(docs/08), 제출 시작 시각.

대화가 길어지면 언제든: PLAN 상황판을 갱신하고 새 세션에서 "AGENTS.md와 PLAN.md 읽고 이어서".
