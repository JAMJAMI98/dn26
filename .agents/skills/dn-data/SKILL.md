# 데이터 분석 3단계 (주로 창 B. 원본 수정 금지, 계산 코드는 backend/scripts/, 결과는 docs/04·06)

규칙 하나: **모든 분석은 "반영 값 → 어느 결정(D)·설정·개선에 쓰이나"로 끝난다.** 쓰이지 않을 분석은 하지 않는다.
창 B가 병렬로 하므로 첫 완주(창 A)를 늦추지 않는다. 시간을 아끼려고 ②를 건너뛰지 않는다.

## ① 점검 (+10~25분)
- `python3 /tmp/dn/tools/profile.py data/provided/* --out docs/evidence/profile.md`, 참조는 `joincheck.py`
- 키 유일·참조·형식·결측·단위·시간대·ID 표기 변형·반복 값 중복 합산·방향성(A→B≠B→A)·기간 경계(자정·월말·마지막 날)
- docs/04 점검 표에 파일별 한 줄 + 함정과 처리. 이 점검 코드는 창 A가 데이터 적재 검증기로 옮긴다(두 번 만들지 않는다).
- 해석이 필요한 차이 → 2차 담당자 질문 후보(구체 사례·건수 포함).

## ② 탐색·설계 분석 (+20~45분, G2 재료)
아래 유형표에서 해당 줄의 항목을 고른다(3~5개). 각 항목은 docs/04 A절 양식: 질문 → 방법(스크립트) → 숫자(분포는 최대·p95·중앙값) → 결론 한 줄 → 반영 값.
| 과제 유형 | 탐색에서 볼 것 |
|---|---|
| 최적화(배정·경로·일정) | 그룹별 수요 규모, 지역·시간 분포, 개별 최소 비용(하한, 예: 직행 소요), 묶을 수 있는 정도(통합 후보), 현행 실적으로 복원한 기준선 |
| 예측·분류 | 목표 비율·불균형, 시간 순서·누수 위험 열, 그룹(설비·라인)별 차이, 결측 패턴 |
| 이상 탐지·시계열 | 주기·추세·결측 구간, 정상 범위, 라벨 유무·이벤트 수, 센서 간 상관 |
| 텍스트·LLM | 문서 길이·형식·중복, 질문 유형 분포, 정답 근거 위치, 민감정보 여부 |
| 분석 리포트·대시보드 | 핵심 지표 정의(분자·분모), 기간·단위 통일, 이상치, 비교 기준(전년·현행) |
- 끝에 "반영 값 모음" 표를 채운다: 이름 · 값 · 근거 · 설정 위치. 이 표가 G2 제약·지표 표의 재료다.
- 대표 숫자 하나는 다른 방법(csv와 pandas 등)으로 다시 계산해 맞춘다.

## ③ 결과 분석 (첫 완주 이후, 개선마다)
우리 출력을 데이터처럼 본다. 평균만 보고 끝내지 않는다.
| 과제 유형 | 결과에서 볼 것 |
|---|---|
| 최적화 | 개인별 최악값·p95, 자원당 부하, 제약 경계에 붙은 건, 이상해 보이는 결과 3건을 직접 열어 보기 |
| 예측·분류 | 틀린 사례 유형, 그룹별 성능, 임계값별 비용 |
| 이상 탐지·시계열 | 탐지 지연, 오경보가 몰린 구간 |
| 텍스트·LLM | 평가 세트 정답률, 실패한 질문 유형, 근거 없는 답 |
| 리포트 | 화면 숫자를 원자료에서 다시 계산해 대조, 해석 문장의 근거 |
- 결과는 docs/06 실험 표 한 줄 + "다음 개선 대상" 한 줄. 창 A는 이것으로 다음 개선을 고른다.
- 지표 상한을 넘는 건이 있으면 숨기지 않고 docs/07에 FAIL 또는 [가정]으로 남긴다.

하지 말 것: 결정에 쓰이지 않는 흥미 분석(민원·요일 패턴 등)을 파고들기, 보고서 꾸미기, 같은 주제를 세 번 파고들기.
