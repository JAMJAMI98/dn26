# 데이터 점검 (원본은 읽기만)

## 0. 도구부터
- `python3 ~/dn/tools/profile.py data/*.csv --out outputs/profile.md` (없으면 아래 항목을 직접 스크립트로)
- 조인 키가 있으면 `python3 ~/dn/tools/joincheck.py a.csv:열 b.csv:열 [--alias b.csv:별칭열]`로 매칭 실패 0을 확인한다
- 제조·공정 데이터면 `~/dn/templates/DOMAIN.md`를 복사해 `DOMAIN.md`로 쓰고, 4절 원인 추적 절차를 따른다

## 1. 프로파일 (스크립트 하나, 출력 30줄 이내)
- 파일별 행·열 수, 타입, 앞 3행
- 결측이 있는 열과 비율, 완전 중복 행 수, 값이 하나뿐인 열
- 키 후보: 고유값 수 대 행 수
- 시간 열: 범위, 형식, **시간대 표기 여부**(표기 없으면 임의로 정하지 않고 질문 후보로)
- 수치 열: min / 중앙값 / max. 물리적으로 불가능한 값(음수, 0, 범위 밖)
- 범주·코드 열: 값 목록과 빈도 (표기 흔들림 확인)

## 2. 파일 간 연결
- 조인 키의 **표기가 파일마다 같은지** 본다. 대소문자, 구분자(`-`, `_`, 없음), 0 패딩, 약어.
- 정규화 규칙을 만들면 **매칭 실패 건수를 출력해 0인지 확인**하고, 남은 실패는 목록으로 보여 준다. 기준 마스터의 별칭 목록이 불완전할 수 있다.
- 조인 전후 행 수를 출력한다. 늘었으면 키 중복부터 본다.
- 문자열 ID를 숫자로 바꾸지 않는다 (앞자리 0, 큰 정수 깨짐).

## 3. 집계 함정
- **분모가 무엇인가**: 전체인가, 해당 그룹인가. 폐기·취소·테스트 건을 분모에서 빼는가.
- **집계 단위를 맞춘다**: 행 단위(측정, 웨이퍼, 다이)와 판단 단위(lot, 설비, 일자)가 다르면 먼저 판단 단위로 집계한다.
- 그룹 비율의 단순 평균과 전체 비율은 다르다. 가중 여부를 밝힌다.
- 전체 경향과 그룹별 경향이 반대면 보고한다 (심슨의 역설).
- 고유 개수와 건수를 구분한다.

## 4. 제조·운영 데이터에서 자주 나오는 함정
- **판정 단계와 원인 단계 혼동**: 검사·측정·판정 설비는 불량을 "발견"한 곳이지 "만든" 곳이 아니다. 원인 후보에서 분리한다.
- **재검사·재측정 중복**: 같은 대상이 여러 번 측정되면 어느 것을 쓸지(첫 측정, 최종 측정) 정한다. 섞으면 분모가 중복되고 불량이 과대 집계된다.
- **설비·장비 ID 표기 차이**: 시스템마다 같은 설비를 다르게 부른다. 한 설비 코드가 두 모듈에 겹쳐 모호하면 "모호"로 표시하고 임의로 붙이지 않는다.
- **시간대와 시점**: 시스템마다 UTC와 KST가 섞일 수 있다. 정비·변경 이력과 공정 이력을 비교하기 전에 맞춘다.
- **변경점 구간**: 정비, 부품 교체, 레시피 변경 직후부터 문제가 시작되는 경우가 많다. 전후 구간으로 나눠 비교한다.
- **폐기·미검사 건**: 결과가 없는 대상을 0으로 채우지 않는다. 분모에서 빼고 개수는 따로 보고한다.
- **상관 ≠ 인과**: 결과는 "원인 후보 + 근거(기간, 대상 목록, 비교 수치)"로 낸다. 단정하지 않는다.
- **결측을 0으로 채우지 않는다**: 측정 안 함과 0은 다르다. 대체하면 플래그 열을 남긴다.

## 5. 보고
`발견 / 영향 / 처리 제안` 3열 표, 최대 8행. 정의를 바꾸는 처리(제외 대상, 기준 변경)는 사용자가 고른다.
- 처리 결정은 `LOG.md`에 `D` 항목으로, 새 규칙은 `AGENTS.md` "이 과제 고유 규칙"에 한 줄.
- 의미가 불확실한 열, 코드값, 단위는 담당자 질문 후보로 넘긴다.
- 점검 스크립트는 `outputs/` 옆 `scripts/`에 두고 커밋한다 (검증 증거).
