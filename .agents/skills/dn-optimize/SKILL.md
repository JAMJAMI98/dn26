# 최적화형 과제 (설계는 창 A, 실험 실행은 A·B)

1. **문제 유형 식별**: 알려진 유형에 대응시킨다(예: 차량 경로 VRP, 시설 위치·배정, 집합 덮개(커버리지), 일정·작업 배정, 빈 패킹, 배낭 문제). 과제 단계가 유형의 단계와 어떻게 맞는지 표로.
2. **해법 계열 2~3개**를 비교 후보로 정한다(예: 단계 분해 + 휴리스틱, 묶음 먼저 경로 나중, 절약 알고리즘, 탐욕 + 국소 개선, 정수계획은 규모가 작을 때만). 단계마다 무엇을 최적화하는지 빠뜨리지 않는다(선정 단계를 "가장 가까운 것"으로 고정하면 그 단계는 최적화하지 않은 것).
3. **제약과 목적을 분리**: 반드시 지킬 것(제약, 검사기에 들어감)과 줄일 것(목적). 목적이 여러 개면 가중합 대신 우선순위(사전식)도 검토. 가중치를 쓰면 근거와 민감도를 함께.
4. **기준선**: 현행(데이터로 복원 가능하면) 또는 상식적 단순안. 일부러 나쁜 첫 생성안을 기준선으로 쓰지 않는다.
5. **지표**: 효율(자원 수·총 비용)과 편의(개인별 최대·p95·평균), 제약 위반 건수, 실행 시간. 개인별 최악값을 반드시 본다.
6. **단순해 먼저**(첫 완주) → 후보를 `domains/<문제>/solvers/`에 나란히 → `make experiment`(같은 데이터·같은 지표) → docs/06 표에 한 줄씩 → 이긴 것을 기본값으로(LOG D).
7. **답 없는 가정**(예: 처리 시간, 이동 속도)은 값 2~3개로 민감도를 돌려 영향 크기를 docs/06에 남긴다.
8. **실현 불가능**하면 억지로 만들지 말고 어느 제약 때문인지 보고한다.
9. 계산이 수 초 이상이면 작업 상태 API로 돌리고, 같은 입력은 같은 결과(정렬·동점 규칙, 난수 시드 고정).
