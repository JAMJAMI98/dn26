# 웹 화면

원칙: **한 사용자, 한 흐름, 한 화면.** 화면은 BRIEF의 핵심 질문 3개에 답하는 곳이다.

## 1. 만들기 전 (5분, PLAN.md에 텍스트로)
- 누가(담당자 말 그대로) 무엇을 보려고 들어오나 한 줄
- 핵심 흐름 하나: 입력(무엇을 고르나) → 결과(숫자·표·차트) → 근거(출처, 처리 경로, 가정)
- 화면 스케치를 글로: 위에서 아래로 블록 3~5개. 각 블록이 어느 R번호를 채우는지 표시
- 상태 4개를 정한다: 처음(빈 화면 안내) / 처리 중 / 오류(사용자 말로, 다음 행동 포함) / 결과

## 2. 만들 때
- 스택: 과제가 정한 것 > 이미 설치된 것 > `~/dn/tools/webskel`(표준 라이브러리, 정적 파일 + API를 한 서버에서). 새 프레임워크 설치는 승인 후에만
- **API 먼저**: `/api/...`를 만들고 `curl`로 정상·빈·잘못된 입력을 확인한 뒤 화면을 붙인다
- 외부 CDN·웹폰트·외부 이미지에 기대지 않는다 (네트워크가 막혀 있을 수 있다). 필요한 JS·CSS는 파일로 둔다
- 서버 `0.0.0.0`, 포트는 환경변수로. 정적 파일과 API를 같은 서버에서 내보내 CORS 문제를 피한다
- 입력 검증은 서버에서 한다. 화면 검증은 보조
- 결과 옆에 근거를 붙인다: 데이터 기간·건수, 계산 기준, [가정] 표시. 숫자에는 단위
- 화면 위계: 제목 → 핵심 숫자·결론 → 표·차트 → 근거·가정. 장식보다 읽기 쉬움. 표는 숫자 오른쪽 정렬, 정렬 기준 명시
- 한글이 깨지지 않는지 (`<meta charset="utf-8">`, 응답 헤더 `charset=utf-8`)
- 큰 데이터는 서버에서 집계·페이지 나눔 후 보낸다. 전체를 화면에 그리지 않는다

## 3. 확인 (증거는 `ev.py`로)
- `curl -s -o /dev/null -w "%{http_code}" localhost:$PORT/` → 200
- `curl -s localhost:$PORT/ | grep -c "핵심 문구"` → 화면에 핵심 블록이 실제로 나오는지
- API 3종(정상·빈·잘못된 입력) 응답 코드와 메시지
- 브라우저 자동 확인은 이미 설치돼 있을 때만: `python3 -c "import playwright"`가 되면 페이지를 열어 스크린샷을 `outputs/screens/`에 저장. 없으면 설치하지 않는다
- 서버를 껐다 켜도 같은 화면인지 (메모리 상태에만 기대지 않나)
- 사용자가 미리보기에서 누를 순서 3~5단계를 적어 `HUMAN_CHECK`로 넘긴다

## 4. 흔한 실패
- `127.0.0.1`·`localhost`에 바인딩 → 미리보기에서 안 열린다
- 서버를 Codex 대화 안에서 띄워 세션이 멈춘다 → 전용 터미널에서 띄운다
- 포트 충돌 → 이미 떠 있는 프로세스 확인 후 다른 포트
- 개발 서버 허용 호스트 오류 → 미리보기 주소의 도메인 추가 (Vite: `server.allowedHosts`)
- 오류가 나면 빈 화면 → 상태 4개 중 "오류"가 실제로 보이는지 일부러 실패 입력으로 확인
