# 구현 (+45~125분, 창 A 중심, 화면은 창 C)

## 1. 첫 완주 (+75분까지) — 품질보다 끝까지
입력 적용 → **가장 단순한 방법**의 계산(domains) → 규칙 검사 → 저장 → 조회(두 역할) → 내보내기 → health. 기간·범위는 작게(예: 하루치)로 시작해도 된다.
완료 기준: `make test` PASS, curl로 전 구간 확인, 커밋 `feat: 첫 완주`. 그다음 G3에서 사용자가 화면을 직접 본다.

## 2. 개선 루프 (G3에서 고른 1~2개)
- 개선 대상은 `$dn-data` ③ 결과 분석(창 B)이 docs/06에 적은 "다음 개선 대상"에서 고른다.
- 한 턴 = 목표 하나. 끝나면 테스트 → 지표 표(docs/06 또는 07) → 커밋. 커밋 메시지 "무엇을 왜" 한 줄, R·C·D 번호.
- 계산 방법 개선은 domains에 후보를 **나란히** 추가하고 `make experiment`로 같은 지표 비교 → 이긴 것을 설정 한 줄로 기본값 교체.
- 사용자가 결과를 바꾸면 LOG에 `[수정] E | 시각 | AI가 처음 한 것 → 바꾼 것 ← 이유`.

## 3. 지시를 받을 때 기대하는 형식 (아니면 이 형식으로 되묻지 말고 해석해서 진행하고 해석을 한 줄 보고)
`목표 / 이번 턴(할 것·하지 말 것) / 완료 기준 / 시간 / 보고`
화면 수정: `[부품] [현재] [원하는 것] [완료 기준] [건드리지 말 것]`
"설명만:"으로 시작하면 코드를 고치지 않고 설명만 한다.

## 4. 멈출 때
- 같은 실패를 두 번 고쳐도 같으면 멈추고 보고(재현 명령·원인 후보 2개).
- G4(+125분) 이후 새 기능 금지. 버그·검증·문서만.
- 종료 20분 전 최종 커밋. 커밋이 권한 문제로 실패하면 우회하지 말고 사용자가 칠 명령 한 줄을 준다.
