# 원인 분석 (분석은 창 B, 계산 코드는 domains 또는 scripts, 결과는 docs/04·06)

원칙: **원인은 단정하지 않고 후보 순위 + 근거 + 반증 결과로 낸다. 최종 판단은 담당자.**

1. **문제를 숫자로 고정**: 무엇이(지표) / 언제부터(기간) / 얼마나(기준 대비 차이) / 어디서(대상 단위). 기준 기간과 문제 기간을 담당자와 맞춘다. 판단 단위(건·묶음·사람·설비)가 행 단위와 다르면 먼저 묶는다.
2. **나눠 보기**: 차이를 구성 요소로 쪼갠다. 그룹별(대상·장소·담당·조건·시간대) 표에서 차이가 몰린 곳을 찾는다. 비율 지표는 분자와 분모를 따로 본다(분모 변화가 원인일 수 있다). 구성비가 바뀐 효과와 그룹 안 변화 효과를 구분한다.
3. **공통점 찾기**: 나쁜 건들이 공통으로 거친 것(단계·자원·공급원·조건)을 **고유 건수**로 순위. 원인 후보는 문제 발생 **이전** 기록만. 기록·검사만 하는 단계는 원인 후보에서 빼되 이유를 적는다. 건수가 너무 적은 후보는 표시만 한다.
4. **변화점**: 후보에 대해 문제 시작 전후 일정 기간의 변경 기록(교체·정비·조건 변경·입고·정책 변경)을 시간대를 맞춰 붙인다.
5. **반증**: 같은 후보의 다른 기간은 정상인가 / 같은 기간 다른 후보는 정상인가 / 상위 묶음 안에서 문제가 **몰리나 흩어지나**(몰리면 그 묶음이 거친 자원, 흩어지면 공통 투입물을 의심). 반증에서 살아남은 후보만 위로.
6. **수렴**: 서로 다른 진입점(급증 기간, 집중 패턴, 변화점)이 같은 후보로 모이는지 본다.
7. **출력**(화면·docs): 후보 순위 표 = 후보 / 근거 숫자(기간·대상 수·차이) / 반증 결과 / 확인 못 한 것. "데이터 사실"과 "추론"을 칸으로 나눈다. 권고는 "확인할 것" 수준. 데이터가 없는 후보는 보류로 표시.
8. **담당자 질문**(2·3차): "후보 A가 이 기간에 몰렸는데, 그때 바뀐 것이 있었나요?"처럼 구체 사례로. 상관을 인과로 말하지 않는다.
9. **검증**: 후보 순위 계산을 다른 방법(직접 집계)으로 재현, 일부러 원인을 심은 작은 데이터로 그 원인이 1위로 나오는지 테스트.

같은 분야의 일반 지식이 필요하면 `/tmp/dn/knowledge/`에서 해당 절만 읽는다(README 참고). 지식은 질문 거리이지 답이 아니다.
