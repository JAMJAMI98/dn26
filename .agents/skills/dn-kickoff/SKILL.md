# 시작 (0~10분, 창 A)

1. 읽기만 한다: README, 데이터 설명, 스키마·예시 파일, 디렉터리, 제출물 목록. 환경: `python3 -V; node -v; git --version; date`.
2. **과제 모양 판별**(여러 개 가능)과 켤 모듈을 선언한다.
   - 여러 해 중 골라야 함(배정·경로·일정·배치) → `$dn-optimize`
   - 예측·분류·이상 탐지 → `$dn-model`
   - 앱 안 LLM 기능 → `$dn-llm`
   - 화면이 있음 → `$dn-ui`, 로그인·DB·배포·데이터 교체 중 2개 이상 → 서비스형(`$dn-stack` A안 전체)
3. `docs/02_requirements.md`: README 원문 번호 그대로 대응표. 숫자·파일명·경로·형식은 복사. 기능 R, 반드시 지킬 조건 C로 번호.
4. `docs/01_brief.md` 초안: 다시 정한 문제, 성공 기준 3개(숫자), 안 할 것, 제출물, 가정. **답 없는 것은 가정값으로 채우고 진행**한다.
5. README·데이터 설명에서 "담당자에게 확인", "해석이 필요한", "관행" 같은 문장을 찾아 1차 질문 후보로 넘긴다(`$dn-interview`).
6. PLAN.md 상황판에 시각표(첫 입력의 시각)를 채운다.
7. 보고(10줄): 요청 한 문장 / 과제 모양·켠 모듈 / 제출물 / 1차 질문 후보 4~5개 / 다음: `$dn-stack`.

하지 말 것: 구현, 긴 분석, 같은 내용을 여러 문서에 반복.
G1(+25분)에 01_brief를 사용자에게 보여 OK를 받는다.
