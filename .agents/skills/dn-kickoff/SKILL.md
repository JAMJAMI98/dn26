# 시작 (0~10분, 창 A)

1. 읽기만 한다: README, 데이터 설명, 스키마·예시 파일, 디렉터리, 제출물 목록. 환경: `python3 -V; node -v; git --version; date`.
2. **과제 모양 판별**(여러 개 가능)과 켤 모듈을 선언한다.
   - 여러 해 중 골라야 함(배정·경로·일정·배치) → `$dn-optimize`
   - 예측·분류·이상 탐지·추천 → `$dn-model`
   - 앱 안 LLM 기능 → `$dn-llm`
   - 나빠진 이유·차이의 이유를 데이터로 좁혀야 함(원인·영향 요인·비교 진단) → `$dn-cause`
   - 화면이 있음 → `$dn-ui`, 로그인·DB·배포·데이터 교체 중 2개 이상 → 서비스형(`$dn-stack` 골격 전체)
   - **이미 돌아가는 코드가 있음(기존 앱 수정·버그 수정형)** → 골격을 복사하지 않는다. 기존 구조·명령·테스트를 그대로 쓰고, 먼저 기존 테스트·실행을 돌려 기준 상태를 LOG에 남긴다. 키트에서는 문서·기록·검증 방식만 쓴다. 바꾸는 파일은 최소로.
   - 분석 리포트·대시보드·비교 자료가 결과물 → `$dn-report`. 화면·로그인이 필요 없으면 골격 없이 계산 스크립트 + 결과 파일.
   - 게임·인터랙티브 프로토타입 → `$dn-ui`. 서버·로그인이 필요 없으면 B안 골격의 frontend만 쓰고 규칙은 순수 JS 모듈로.
   - 유형별 기준(해당 줄을 docs/01 성공 기준과 docs/05에 옮긴다. 숫자는 담당자 답으로 정한다):

| 유형 | 핵심 지표(평균만 쓰지 않는다) | 검증 | 흔한 함정 |
|---|---|---|---|
| 최적화(배정·경로·일정·배치) | 제약 위반 0, 개인별 최악값·p95, 기준선 대비 개선 | 규칙별 고의 위반 테스트, 독립 재계산 | 평균만 좋아지고 한 사람이 몰림, 반복·편중 |
| 승인·업무 흐름(요청·승인·반려) | 상태 전이 규칙 위반 0, 처리 시간 | 허용 안 되는 전이·권한 테스트(작성자 본인 승인 등), 이력 남는지 | 상태를 덮어써 이력이 사라짐, 금액·한도 경계값 |
| 심사·검토 판정(변경·위험·적격성) | 놓침과 헛경보 건수, 판정마다 근거 문장 | 경계값 사례 표, 같은 입력 같은 판정 | 근거 없는 점수, 보류·사람 검토 경로 없음 |
| 예측·이상 탐지·관리도 | 재현율·정밀도 또는 MAE, 탐지 지연 | 시간 순 분할, 누수 열 점검, 관리 한계 재계산 | 미래 정보 누수, 관리도 규칙(연속 이탈 등)을 담당자에게 안 물음 |
| 추천 | 상위 k개 적중률, 다양성·중복, 신규 사용자 처리 | 시간 기준 분할, 인기순 기준선과 비교 | 인기 상품만 반복, 이미 산 것·품절 추천 |
| LLM(답변 초안·피드백·학습 도우미) | 평가 세트 정답률, 근거 없는 답 0, 거절해야 할 질문 처리 | 고정 평가 세트 10~20개, 출처 표시 확인 | 같은 질문에 답이 바뀜, 민감정보 전송, 키 없을 때 화면 깨짐 |
| 원인 분석(`$dn-cause`) | 후보 순위와 근거 숫자, 반증 통과 여부 | 원인을 심은 작은 데이터에서 1위로 나오나, 다른 방법 집계와 일치 | 상관을 인과로 말함, 문제 이후 기록을 원인으로 씀, 분모 변화 무시 |
| 분석 리포트·대시보드(`$dn-report`) | 지표 정의(분자·분모·기간), 비교 기준 | 화면 숫자를 원자료에서 다시 계산해 대조 | 단위·기간 섞임, 출처 없는 숫자, 해석과 사실 섞임 |
| 운영 정책·이슈 정리 | 이슈별 영향·담당·조치·기한, 정책 충돌 0 | 원문(로그·정책) 줄 번호로 근거 대조 | 추측을 사실처럼 씀, 중복 이슈 |
| 게임·인터랙티브 프로토타입 | 규칙 구현 여부(승패·충돌·시간 제한), 프레임 끊김 없음 | 규칙은 순수 함수 `step(상태, 입력, 시간)`로 분리해 `node --test`, 난수 시드 고정 | 화면 코드에 규칙이 섞여 테스트 불가, 탭 전환 후 시간 폭주 |
| 기존 코드 수정·버그 | 기존 테스트 통과 유지, 재현 테스트가 수정 전 실패·후 통과 | 수정 전 실패 출력을 LOG에 남김 | 관계없는 파일까지 고침, 구조 갈아엎기 |
3. `docs/02_requirements.md`: README 원문 번호 그대로 대응표와 **용어 표**(README·담당자 표현 그대로, 모르는 업무 용어는 1차 질문 후보). 숫자·파일명·경로·형식은 복사. 기능 R, 반드시 지킬 조건 C로 번호.
4. `docs/01_brief.md` 초안: 다시 정한 문제, 성공 기준 3개(숫자), 안 할 것, 제출물, 가정. **답 없는 것은 가정값으로 채우고 진행**한다.
5. 분야 배경이 필요하면 `/tmp/dn/knowledge/README.md`를 보고 맞는 파일의 **필요한 절만** 읽는다. 거기서 나온 것은 [일반]으로 표시하고 담당자 질문 후보로 돌린다(답으로 쓰지 않는다).
6. README·데이터 설명에서 "담당자에게 확인", "해석이 필요한", "관행" 같은 문장을 찾아 1차 질문 후보로 넘긴다(`$dn-interview`).
7. PLAN.md 상황판에 시각표(첫 입력의 시각)를 채운다.
8. 보고(10줄): 요청 한 문장 / 과제 모양·켠 모듈 / 제출물 / 1차 질문 후보 4~5개 / 다음: `$dn-stack`.

하지 말 것: 구현, 긴 분석, 같은 내용을 여러 문서에 반복.
