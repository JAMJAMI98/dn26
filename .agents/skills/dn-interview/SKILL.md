# 담당자 질문 (초안은 창 B, 발송은 사용자)

## 원칙
- 총 6~8개를 2~3회에 나눈다. **질문 하나 = 답에 따라 바뀌는 결정 하나**. 답이 코드·설정을 바꾸지 않으면 묻지 않는다.
- 사실·선호·기준만 묻는다. 구현 방법·정답·파일로 계산할 수 있는 숫자는 묻지 않는다. 같은 주제를 세 번 파고들지 않는다.
- 질문은 한 대상 + 구체 상황 + 열린 질문. 전문 용어 대신 현장 말.

## 1차 (+10~20분, 4~5개) 틀
1. 좋고 나쁨의 기준: "결과를 보시면 무엇으로 좋다/나쁘다 판단하세요? 가장 큰 불만 하나는요?"
2. 넘으면 안 되는 숫자: "○○가 몇 분/몇 개를 넘으면 문제가 되나요? 꼭 지켜야 하나요, 가능하면인가요?"
3. 상충 우선순위: "A와 B가 부딪히면 무엇이 먼저인가요?"
4. README·데이터 설명이 "담당자에게 확인"이라 한 것 / 해석 문구(날짜 집계 관행, 상태 차이 등)
5. 예외: "규칙에 안 맞는 사람·건은 지금 어떻게 처리하나요?"
## 2차 (+25~45분, 2~3개 — 답이 G2에 들어가야 한다)
데이터에서 찾은 구체 사례: "○○ 파일에 △△인 행이 N건 있는데, 업무상 어떻게 보나요?"
## 3차 (+80~100분, 1개)
결과 한 장면: "이런 결과(핵심 숫자 2~3개)면 현장에서 받아들여지나요?"

## 답을 받으면 (한 번에 두 줄만)
- `docs/03_interview.md` 표에 답 원문 한 줄.
- 결정이 바뀌면 `docs/05_design.md` 결정 표 또는 제약·지표 표에 한 줄. 수치 답은 **제약 후보**로 올려 G2에서 사용자가 "반드시/가능하면"을 정한다. "정해지지 않은 값"이라며 쓰지 않고 두지 않는다.
- 답이 늦으면 가정값으로 진행하고 설정값 이름을 docs/01 가정에 적는다. 답이 오면 숫자만 바꾼다.
하지 말 것: 답 하나마다 PLAN·AGENTS·여러 문서 갱신, 문서 검증 V.
