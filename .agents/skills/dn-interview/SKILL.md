# 담당자 인터뷰

## 1. 질문 만들기
먼저 **이 시스템이 답해야 할 핵심 질문 3개**(현업이 실제로 던질 질문, 예: "지난주 불량이 왜 늘었나?")를 초안으로 쓰고 담당자에게 맞는지 확인한다. 이후 데이터 구조·화면·검증은 이 3개에 답할 수 있는지로 판단한다.
담당자는 막연한 질문에는 되묻고, 구체적인 대상을 짚은 질문에 숨은 조건을 말한다. 작은 사실 질문에서 시작해 점점 깊게 물을수록 정보가 많이 나온다. 담당자는 무엇을 만들지 알려 주지 않고 현장의 문제만 말한다. "할 일을 목록으로 정리해 달라"처럼 답을 통째로 요구하지 않는다.
- 질문 모양: **대상 하나 + 구체 상황 + 열린 질문**
  - 좋음: "`status` 열의 SCRAP lot은 수율 분모에서 어떻게 보시나요?"
  - 나쁨: "주의할 점 있나요?", "뭘 만들면 되나요?", "AI로 자동화하면 어떨까요?"
- 순서: 최근 실제 사례 → 지금의 처리 방식과 걸리는 시간 → 숫자(기준값, 목표) → 사람(누가 쓰고 누가 보나) → 경계(예외, 제외 대상, 이번 범위 밖)
- 파일로 확인할 수 있는 사실은 묻지 말고 직접 본다. 데이터에서 본 이상한 점은 하나씩 질문으로 바꾼다.
- 질문마다 "답에 따라 바뀌는 결정"을 한 줄 붙인다. 보통 4~8개. 처음 만들 것을 바꾸지 않는 질문은 버린다.
- 질문은 사용자가 메신저로 직접 보낸다. 한 번에 1~2개씩.

## 2. 답 기록 (PLAN.md)
```
## 담당자 Q&A
### Q1. (질문)
- 답: (요약. 숫자와 고유명사는 그대로)
- 규칙: (이 답에서 생긴 지켜야 할 조건 / 없으면 "사정만 들음")
- 다음 질문: (새로 생긴 질문)
```
규칙이 생기면 `AGENTS.md`의 "이 과제 고유 규칙"에도 한 줄 추가한다.


## 3. 답이 쌓이면
- 답으로 생긴 규칙은 `AGENTS.md` "이 과제 고유 규칙"과 (있으면) `DOMAIN.md` 7절에 한 줄씩
- 요구가 새로 생기거나 바뀌면 `PLAN.md` 요구 목록(R번호)을 갱신하고 `LOG.md`에 D 항목으로 변경 이유
- 질문을 더 해도 처음 만들 것이 바뀌지 않으면 멈추고 구현으로 (보통 20분 이내)
- 구현 중에도 막히면 질문 1개씩 추가로 보낸다 (답을 기다리는 동안 [가정]으로 진행)
- 구현 중간에 코드의 상수·임계값·제외 조건·기간 경계를 훑는다 (`grep -nE "[0-9]{2,}|THRESHOLD|LIMIT|보통|일반적"` 수준). 출처(Q번호, README, 데이터 점검)가 없으면 [가정]이다.
- [가정]마다 "이 값이 틀리면 무엇이 달라지나"를 붙여 질문 후보로 올린다. 답이 오기 전엔 기본값을 설정 파일에 두고 화면·README에 가정으로 표시한다.
