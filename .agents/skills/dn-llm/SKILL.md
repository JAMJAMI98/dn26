# 앱 안의 LLM 기능

원칙: **LLM은 말이 필요한 곳에만. 판정·계산·필터·쿼리 조립은 고정 코드.**

## 1. 설계 전에 정할 것
- 이 기능에서 LLM이 맡는 일 한 문장 (예: "자연어 질문 → 조회 인자 JSON", "결과 표 → 3줄 요약")
- 나머지(계산, 필터, 쿼리 조립, 날짜 해석)는 코드가 한다. 날짜 표현("지난주")은 규칙 기반 해석기로, 기준은 시스템 시계가 아니라 **데이터의 최신 기간**인지 담당자에게 확인
- OpenAI API·SDK 사용법(호출 형식, 파라미터, 구조화 출력)이 막히면 추측하지 말고 Codex 기본 스킬 **OpenAI Docs**로 공식 문서를 확인한다 (과제 데이터는 넣지 않는다)
- 과제가 제공한 환경변수만 쓴다 (`OPENAI_API_KEY`, `OPENAI_BASE_URL`, 모델명 변수 등). 값은 출력·커밋·로그에 남기지 않는다. 존재 여부만 확인: `[ -n "$OPENAI_API_KEY" ] && echo 있음`
- 민감정보(이름, 연락처, 내부 ID 등)가 있으면 **가린 뒤** 보낸다. `/tmp/dn/tools/mask.py`를 복사해 쓴다 (`from mask import mask_text, unmask_text`; 꼬리표 방식이라 같은 값은 같은 꼬리표, 응답 후 복원 가능). 패턴 밖 형식(사번, 고객코드)은 `names`나 CSV `--cols`로 추가하고, 가린 건수를 V 항목에 남긴다. 복원용 map 파일은 `.gitignore`. "가려야 한다"는 조건은 LLM을 빼라는 뜻이 아니라 가린 뒤 쓰라는 뜻이다

## 2. 입출력 계약
- 출력은 **JSON 스키마**로 받고 코드로 검증한다. 모르는 필드·타입·값은 버리고 경고를 남긴다
- 자유 생성 대신 **고정 템플릿의 슬롯만 채우게** 한다. 쿼리·SQL은 LLM이 쓰지 않고 빌더 코드가 파라미터화해 조립한다
- 판정 결과를 내는 기능이면 판정도 4상태로: 해당 / 예외(규칙상 제외) / 검토 필요(근거 부족·애매) / 판단 불가(데이터 없음). 억지로 둘 중 하나로 만들지 않는다
- 응답 상태를 나눈다: `ok` / `summarized`(잘라서 줄임) / `clarification`(빠진 인자 되묻기) / `error`. 채운 인자와 빠진 인자를 같이 반환한다
- LLM에 넘기는 데이터는 **최소 컬럼·집계 결과** 위주. 크기 예산을 서버가 강제하고, 넘치면 줄이고 "요약됨"으로 표시
- 요약에는 숫자를 **그대로 복사**하게 하고 계산시키지 않는다. "데이터 사실"과 "추론"을 구획으로 나누게 한다. 데이터가 없으면 "근거 없음"으로 끝낸다
- 표본(앞 N행)과 전체 합계를 같이 넘기면 N을 전체로 착각한다 → 합계는 별도 필드로 명시
- 출력 토큰이 모자라면 JSON이 끊긴다 → 최대 출력 길이를 충분히, 입력은 LIMIT
- **이어 묻기**: 직전 응답의 대상(ID 목록, 기간, 필터)을 세션 상태로 저장하고, "그거/그중"은 LLM이 아니라 코드가 그 상태로 해석한다
- 조회 한도·깊이·기간 같은 값은 LLM이 정하지 않고 서버 기본값으로 고정한다 (LLM에 맡기면 계속 튜닝하게 된다)
- 다단계 탐색이 필요하면 한 번의 큰 호출 대신 단계별 호출(1차 결과 → 다음 인자)로 나눈다. 깊은 다중 연결 조회는 깊이 상한을 둔다
- 도구 호출의 요청·응답을 로그 파일에 남겨 나중에 대조할 수 있게 한다 (키·개인정보 제외)

- **분류·라우팅**: 한 번에 여러 갈래로 나누는 1단 분류. 분기는 앞 단계가 낸 JSON 필드(참/거짓, 정해진 값 목록)만 보고 코드가 정한다. 애매하면 가장 안전한 일반 경로. 분류 설명에 키워드 하나가 있으면 쏠림이 생긴다 → 포함·제외 예시를 함께 둔다
- **자연어 → SQL**이 필요하면: 부정확한 테이블 설명은 없는 것보다 나쁘다 (컬럼 이름·설명부터 명확히). 모호한 질문은 실행 전에 되묻는다. 정답이 0행인 질문은 결과 비교가 거짓 통과가 되므로 실행 성공·테이블 선택으로 평가한다

## 3. 실패 대비
- 타임아웃, 재시도 1회, 그래도 실패하면 **LLM 없이 동작하는 대체 경로**(규칙 기반 결과 또는 원자료 표)
- JSON 파싱 실패 → 대체 경로, 사용자에게 상태 표시
- 외부 호출 실패가 서버 전체를 멈추지 않게 요청 단위로 격리
- 테스트는 실제 키 없이도 돌게: 가짜 LLM(고정 응답 함수)로 단위 테스트, 실제 호출은 1~2건만 수동 확인

## 4. 검증 (dn-verify와 함께)
- 정상 질문 1개, 모호한 질문 1개(되묻는가), 범위 밖 질문 1개, 민감정보 포함 입력 1개(가려지는가), LLM 실패 1개(대체 동작)
- **전후 비교**: 같은 질문에 "LLM만" vs "우리 구조(규칙·데이터 근거)" 답을 나란히 남기면 설계 효과를 화면으로 보여줄 수 있다
- LLM이 만든 설명·분류가 많으면 다른 모델(가벼운 모델)로 한 번 더 생성해 다른 결과가 나온 항목만 확인한다 (행 밀림·오분류 탐지)
- LLM이 낸 인자·결과를 원자료로 다시 계산해 대조 (3자 대조: 원천 ↔ 중간 결과 ↔ LLM 응답)
- 결과를 `ev.py`로 V 항목에 남긴다
